# 메모리 검색 평가 (P3c)

장기 메모리 검색 변형을 평가셋으로 비교한 기록. 임베딩(P3d)을 도입할지 판단하는 기준선이다.

## 실행

```bash
bun run --filter '@proprix/daemon' memory:eval                     # 합성 예시셋
bun run --filter '@proprix/daemon' memory:eval -- --misses         # 놓친 질문까지
bun run --filter '@proprix/daemon' memory:eval -- --data=apps/daemon/src/memory/eval/data/personal.json
```

- 평가셋 형식: `apps/daemon/src/memory/eval/data/example.json` (기억 `memories` + 질문 `queries`).
  - 기억: `key`, `kind`, `content`(원문), `contentEn`(영어본), `importance`, `supersededBy`(대체한 기억 key), `expired`.
  - 질문: `q`, `qEn`(영어 번역 — 번역 변형용, 미리 넣어 두면 평가에 LLM 호출이 없다), `type`, `expect`, `allow`, `forbid`.
- 개인 평가셋은 `data/` 아래에 두면 `.gitignore` 로 커밋되지 않는다 (`example.*` 만 커밋).

## 지표 (top-5)

| 지표 | 정의 |
|---|---|
| Recall@5 | 질문마다 기대 기억 중 top-5 에 든 비율의 평균 (기대 기억이 없는 질문은 제외) |
| Hit@5 | 기대 기억이 하나라도 top-5 에 든 질문 비율 |
| 잘못된 기억 | 금지 기억(대체된 옛 선호·만료된 일정)이 top-5 에 들어온 질문 비율 |
| 무관 비율 | top-5 결과 중 기대·허용 목록에 없는 것의 비율 (결과가 있는 질문만) |
| 빈 결과 | 기대 기억이 있는데 아무것도 못 찾은 질문 비율 |
| p50 / p95 | 검색 1회 시간 (ms, 메모리 DB 기억 40개) |

질문 유형: keyword(같은 단어), paraphrase(다른 표현), past(오래전에 말한 사실), changed(바뀐 선호).

## 해석

- **trigram·2자 부분 일치는 이 평가셋에서 이득이 없다.** 접두 검색(unicode61, 한글 3자 이상은 끝 한 글자를 뗀 형태 포함)만으로 운영 기본과 같은 재현율을 낸다. 비용이 작아(p95 5ms 미만) 실제 기억에서의 차이를 보기 전까지 운영 기본은 그대로 둔다.
- **약점은 다른 표현(paraphrase)과 바뀐 선호(changed)다.** "반려동물·반려묘 ↔ 고양이", "엄마 ↔ 어머니", "남친 ↔ 남자친구", "녹차 좋아한다고 했지? → 요즘은 디카페인 커피" 처럼 단어가 겹치지 않으면 키워드 검색으로는 찾을 수 없다. P3d 임베딩이 겨냥할 부분이다.
- **질문 번역(영어본 검색)은 다른 표현에서 재현율을 올리지만**(hybrid + 번역: paraphrase 44% → 61%, 전체 74.6% → 79.7%) 무관 비율이 늘고(36% → 45%), 운영에 쓰면 매 턴 LLM 호출이 1회 더 든다. 지금은 운영에 넣지 않고 P3d 결과와 함께 다시 판단한다.
- **영어 불용어 제거**: 번역 질문의 "my·do·what" 이 접두 검색으로 거의 모든 기억에 걸려 무관 비율이 64% 였다. 불용어를 빼서 38% 로 낮췄다 (재현율 78.2% → 74.6%).
- **잘못된 기억 0%**: 대체·만료된 기억은 검색 단계에서 걸러져 어떤 변형에서도 나오지 않는다.
- 이 수치는 합성 평가셋 기준이다. 실제 기억이 쌓이면 개인 평가셋으로 다시 잰다.

### 해석

- **임베딩이 키워드 검색의 약점을 메운다.** 다른 표현 44% → e5 92% / gemma 100%, 바뀐 선호 62.5% → 87.5% / 100%. "반려묘 → 고양이", "엄마 → 어머니", "녹차 좋아한다고 했지? → 요즘은 디카페인 커피" 를 찾는다.
- **벡터 검색은 항상 k개를 채워 무관 비율이 높다**(약 75%). 평균+2σ 이상만 남기면 무관 비율이 키워드 검색 수준(약 34~35%)으로 내려가면서 재현율은 89~96% 를 유지한다.
- **EmbeddingGemma 는 더 정확하지만 질문마다 약 280ms**(e5 는 약 3ms)가 들고 Gemma 약관을 따른다. 채팅 한 턴(수 초)에 비하면 작지만, 같은 정확도 차이가 실제 기억에서도 나는지 개인 평가셋으로 확인할 가치가 있다.
- **운영 적용은 보류한다 (사용자 결정 2026-10-28).** 운영 검색은 키워드(hybrid) 그대로이고, 임베딩은 이 평가 도구에서만 쓴다 (`@huggingface/transformers` 는 개발 의존성). 실제 기억이 쌓이면 개인 평가셋으로 다시 재고 켤지 정한다 — 켤 때는 설정에서 모델 선택·첫 사용 시 다운로드·실패 시 키워드 검색으로 자동 전환, z≥2 를 기준으로 한다.
- 합성 평가셋 40개 규모의 결과다. 기억이 수천 개로 늘면 전수 비교 비용과 무관 결과 경향을 다시 확인한다.

## 운영 적용 (2026-10-28)

실계정 확인에서 "내가 뭘 좋아하지?" 가 저장된 선호("녹차를 좋아한다")를 찾지 못했다. 원인은 활용형("좋아하지" ↔ "좋아한다")이 키워드로 맞지 않는 것과, `memory_search` 빈 검색어가 중요도 4 이상만 돌려주던 버그였다. 사용자 결정으로 다음을 운영에 넣었다.

- **한국어 '하다' 활용 어간**: 끝 한 글자를 뗀 형태에 더해, 그 끝이 하·한·할·함·해·했 이면 한 글자를 더 뗀다 ("좋아하지" → "좋아하", "좋아"). 키워드 검색 Recall@5 74.6% → 76.3% (바뀐 선호 62.5% → 75.0%), 무관 비율 36.0% → 38.5%.
- **로컬 임베딩 하이브리드 (선택, 기본 꺼짐)**: 설정 → 기억 검색에서 모델을 고르면 불러와 기억 원문 벡터를 `memory_embeddings` 에 색인하고, 키워드 결과와 RRF 로 합친다. 벡터 후보는 평균+2σ 이상만. 불러오기·추론 실패 시 키워드 검색만.
- **주입 보강**: 활성 기억이 상한(12개) 이하면 전부 넣고, 많으면 핵심(중요도 4 이상) → 하이브리드 검색 → 남는 자리는 중요도·최근 순.

어간 변경 후 같은 평가셋 (5회 반복 대신 1회, CPU):

| 변형 | Recall@5 | Hit@5 | 잘못된 기억 | 무관 비율 | 빈 결과 | p50 ms | p95 ms |
|---|---|---|---|---|---|---|---|
| hybrid (운영 기본) | 76.3% | 76.3% | 0.0% | 38.5% | 13.6% | 2.97 | 5.01 |
| hybrid + embeddinggemma z≥2 (운영, 켰을 때) | 96.3% | 98.3% | 0.0% | 36.3% | 0.0% | 24.10 | 30.27 |

이번 측정에서 EmbeddingGemma 질의 지연은 약 24ms 였다 (P3d 의 약 280ms 는 첫 측정 환경 차이로 보이며, 운영 경로 점검에서도 약 20ms).
